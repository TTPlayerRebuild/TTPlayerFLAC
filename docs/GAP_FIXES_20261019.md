# FLAC / TTA 宿主兼容修复（2026-10-19）

本轮依据原 `ttp_flac.dll` SHA-256 `e2833c023377787fa9705d52215d3a02b7f5a742bdda4012f9d639c2e1f64dbd`、已保存伪代码及2026-10-19插件审计。原DLL保持不变。libFLAC保持1.5.0；官方当前仍为此稳定版，没有仅为改变版本号更换解码核心。

## 1. 直接文件流的可选 Commit

旧宿主直接写文件的IStream可能不实现Commit。现在仅将 `E_NOTIMPL`、`STG_E_INVALIDFUNCTION` 视为该可选操作不支持；仍检查Write实际字节数、SetSize与所有真实I/O错误。磁盘已满、短写和刷新失败仍触发回滚，原样传播HRESULT。

规则同时用于临时文件、备份与保留宿主流的回写分支。成功的ReplaceFileW路径和可选元数据Commit接口保持原事务顺序；没有给原Reader/Metadata增加虚表槽。

## 2. TTA 信息模式和延迟准备

原 `60303E3E` 在Open flags bit0为0时仅调用 `60303C5A` 读取22字节TTA头，播放模式才调用 `60304381` 准备定位表和位流。

现恢复这个轻量信息模式：无前置标签的文件只读取22字节，立即返回采样率、声道、位深和精确毫秒时长。64 KiB位流缓存与定位表延迟到播放Open或首次Read/Seek时准备；头信息能读取不意味着损坏的音频可播放。首次实际解码仍验证表、帧长度和CRC。

重建保留原来已修正的1.25秒时长，不退回原版截断为1秒的行为。信息模式后首次Read会安全准备解码器，不复制原版可能依赖调用方不读PCM的未初始化行为。

## 3. FLAC 混合外部 ID3 迁移

新增对ID3v2.2/2.3全局unsynchronization、v2.3/v2.4扩展头及CRC、v2.4全局/逐帧unsynchronization与footer的处理。

读取基础复用由 `ttpcomm/cmake/sync_sdk.py` 导出的固定SDK快照：`third_party/ttpcomm`，构建时校验清单。插件只使用其中静态的 `tags.h / bytes.h`；不加载新版ttpcomm扩展接口，因此原版宿主仍可使用，也不需要兄弟仓库参与独立构建。

迁移步骤为：验证原header/footer和扩展CRC → 按正确的版本解开unsync/帧边界 → 去除已由宿主提供的已知文字帧 → 保留未知/图片/二进制帧及其状态/格式标志 → 重建正确长度和footer。移除已过期的扩展头和CRC；v2.2/v2.3需重新进行全局unsync，v2.4未知帧保留存储的payload字节。

所有修改仍只进入完整的新临时文件，与native FLAC Comment和封面在同一个事务提交。没有先改原ID3再写FLAC的中间状态，压缩音频帧保持不变。

**仍明确拒绝的边界：** 压缩或加密的已知文字帧，宿主未必已把完整内容交给插件。为避免编辑一个字段时静默丢失其他字段，这类文字修改继续返回E_NOTIMPL并保留整个文件。未知/二进制帧可按opaque帧原样保留；ID3v2.2整标签压缩、非法CRC/长度/保留位同样拒绝。以后扩展需配合可验证的解压及字段迁移策略，不能只取消检查。
