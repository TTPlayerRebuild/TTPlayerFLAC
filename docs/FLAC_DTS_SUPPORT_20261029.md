# FLAC 内 DTS 识别、二次解码与旧宿主兼容

版本：`2026.10.29`。配套 `ttp_ac3dts.dll` 同为 `2026.10.29`。本轮处理“合法 FLAC 无损保存了 DTS 载体，解压后被当作普通 PCM 输出”的兼容缺口。未知 issue 没有提供原始音频，不能据此认定其文件就是 DTS，也不能宣称所有沙沙声的原因都已解决。

## 实际实现

```text
外层 FLAC 文件、标签及图片
  → libFLAC 解压为原始载体字节
  → 有上限的连续 DTS 帧识别
  → 只读、可定位的虚拟 IStream
  → 同目录 ttp_ac3dts.dll 的 DTS Reader
  → 真实 PCM24／float64、声道布局、时长与定位
  → 原版或重建版宿主的音效和设备输出
```

`src/reader.cpp` 保留外层 FLAC 的标签、图片、编辑和提交接口；`src/dts_carrier.h` 提供字节流及插件桥接。没有复制 DTS 解码核心，没有加入新的 FFmpeg 静态库，也不需要修改原版 EXE。嵌套 Reader 使用原 AddIn／Reader COM ABI，其格式经过校验后才交给宿主。

普通 FLAC／TTA 不加载 DTS DLL。检测命中的 FLAC 才按外层插件的绝对目录加载 `ttp_ac3dts.dll`，枚举 Reader 类别及 DTS 扩展名，验证最终输出为合法 PCM／IEEE float／WAVEFORMATEXTENSIBLE。模块引用保持到嵌套 Reader 及其流全部释放，虚拟流不会反向持有外层 Reader 形成引用环。

原宿主依据及 40 字节格式容量见 [原版 ABI 核对](FLAC_DTS_LEGACY_ABI.md)。本轮最终方案由 FLAC Reader 内部完成二次解码，宿主接收最终 PCM，不需要依靠旧宿主支持新扩展接口。

## 检测与边界

- 初始范围为 44.1／48 kHz、16-bit、双声道 FLAC 载体。
- 在任何增益、EQ、Winamp、重采样和设备转换前，检查解压后的原始字节。
- 覆盖 DTS Core 16-bit BE／LE、14-bit BE／LE，以及历史 14-bit 可选末尾部分字。
- 最多预读 256 KiB，通常要求三个完整且格式一致的连续帧；恰好到 EOF 的两个完整帧也可确认。单个同步字或单个帧不会触发。
- 识别后由实际 DTS Reader 初始化并解码，获取真实声道、掩码和输出精度。强匹配之后解码失败会阻断输出，不能回退输出载体噪声。
- 未命中时所有预读 PCM 原样交还。预读到 EOF 后清理旧块，避免重复输出最后一块。
- 前导静音可在探测范围内跳过；不承诺识别任意长前导静音、任意中途混入的码流或仅一个 DTS 帧的极短文件。范围外仍走普通 FLAC 路径。
- STREAMINFO 的总样本数为零时，只有已识别的 DTS 载体需要一次固定内存的扫描以确定虚拟流长度；普通 FLAC 不因此扫描全曲。

虚拟流允许按任意字节定位：先映射到 FLAC 采样位置，再处理块内字节余数，不能假定每次读取或 Seek 都按四字节对齐。它报告只读属性及非真实文件名，拒绝写入／改尺寸，避免内层通用标签服务误操作外层文件。实际元数据始终由 FLAC Reader 管理。

## 依赖缺失与错误

缺失 `ttp_ac3dts.dll`、加载失败、旧 Reader 仍返回压缩格式或实际 DTS 初始化失败时，外层保持可识别的文件接口，但第一次 `Read` 清零长度并返回真实 HRESULT。没有任何预读载体字节交给音频输出。名称显示为 `FLAC / DTS (decoder unavailable)`。

这样处理有明确的原宿主依据：如果 `Open` 失败，宿主可能尝试另一文件解码器；已打开 Reader 的 `Read` 失败则终止当前播放。普通 FLAC 不受这个可选依赖影响。缺插件用例实际返回 `0x8007007E`；原版旧 DTS 插件的拒绝码按实际返回保留。

`Stop` 同时通知嵌套 Reader 与外层输入事件，`Start` 清除事件；定位和取消恢复继续使用 DTS Reader 的实际 PCM 状态。`Commit` 和最终释放先关闭嵌套 Reader，再关闭 FLAC 解码器，最后由原 FLAC 元数据流程写盘。

## 配套 DTS Reader 修正

`ttp_ac3dts/src/dts_reader.cpp` 同时修正两项：

1. 44.1 kHz 精确定位到 `floor(ms × rate / 1000)` 后，保留已满足的请求毫秒。此前再向下换算毫秒会使宿主误认为定位偏早，再额外丢弃一段采样。
2. 当原始 DTS 的时长只是码率估计，且没有得到可靠的整帧长度关系时，按实际压缩包累计样本。处理 14-bit 部分字／外层对齐及尾部填充；恒定整帧文件仍沿用快速路径。需要扫描的文件只保留有限缓冲，打开速度可能受文件长度和外层 FLAC 解压速度影响。

## 验证

相同最终 DLL 在 Windows 11、XP SP3、Win7 SP1 **各通过 63 组**，均为 `FLAC_DTS_CASES=63 FAILURES=0`。

覆盖普通 FLAC、单／双／6／8 声道、超过预读上限的文件、偶然同步字、仅一个 DTS 帧、四种装包和两种采样率、短分块、未知总样本数、静音前缀、尾部填充、FLAC／内层截断、精确定位、CUE、重复 EOF、打开标志 0／1／3、容量哨兵、停止／继续、标签显式提交及最终释放保存、封面保留、缺失和不兼容解码器。

完整 PCM 与独立的同载荷 DTS-WAV 路径对照。普通 PCM 的数据完全不变。直接 Reader 在 flags 0／1 时遵循 DTS Reader 的 PCM24 输出，flags 3 使用 float64；测试分别核对各自实际格式，没有把三种打开方式强行视为同一种位深。

额外回归：既有 AC3/DTS 矩阵和 DTS Express 实际样本复测通过。旧 FLAC 208 项脚本中的六项 ID3 unsynchronization 拒绝断言在修改前 DLL 上也失败，属于此前已支持功能与旧测试预期不符。另一个打开后注入 I/O 故障的短文件被预读完整，实际没有触发底层故障；换用四秒随机音频后，故障、零输出、错误保留与 Seek 恢复均通过。没有为满足旧脚本而撤销已有标签功能或制造额外读取。

原版／重建版宿主验证结果由工作区 `rebuild/docs/FLAC_DTS_IMPLEMENTATION_20261029.md` 汇总。测试为静音集成检查及离线数值比较，不代表所有声卡的实机测听。Win11 代为现代系统验证，没有单独 Win10 实测。

全部测试、探针、样本、原 DLL 与日志仅在私有 `rebuild/tests/flac_dts_20261029`。Actions 不运行、不上传这些测试。XP／Win7 导入扫描通过；现有 SSE2 要求保持不变。

## 安装

关闭播放器后，将两个 `2026.10.29` 运行包中的 DLL 同时放到播放器的 `AddIn` 目录。无需替换原版 EXE。普通 FLAC／TTA 仍只需要 `ttp_flac.dll`；FLAC 内 DTS 使用配套的重建 `ttp_ac3dts.dll`。

运行 ZIP 各自只包含 `AddIn/对应DLL` 与 `SHA256SUMS.txt`；AC3/DTS 对应源码另包。版权和许可证继续保留在仓库及对应源码附件中。
