# ttp_flac 实现与验证

日期：2026-10-04；发行版本：`2026.10.04`。

## 结果

独立项目已实现原 DLL 的 **FLAC Reader、TTA Reader、宿主流接口、定位、标签及 FLAC 封面接口**，可被原版播放器及 TTPlayer Rebuild 加载。FLAC 解码升级至固定版本 libFLAC 1.5.0，TTA 保留原插件的历史浮点分支。

“恢复”以已核实的 ABI、有效文件输出和宿主行为为标准。没有声称与原 DLL 机器码相同，也不复现已确认的内存越界、数据丢失和错误成功返回。以下明确区分兼容行为、修正和扩展。

## 播放与定位

### 公共接口

- 仅导出原有 x86 `ttpGetSoundAddIn`，调用约定 `__stdcall`。
- 第 0 个工厂为 FLAC，第 1 个为 TTA；枚举越界返回 `E_INVALIDARG`。
- 字符串和 WAVEFORMATEX 使用 `CoTaskMemAlloc`；PCM 写入宿主 Buffer。
- 优先查找 `ttpctrl.dll` 的 `CreateStdContent`，兼容 `soundcore.dll` 及主 EXE 导出。FLAC 参数为 5，TTA 为 4。
- 转发扩展流的异步读取槽和事件／超时参数，转发宿主回调；未提供扩展接口时使用 IStream。
- 数据按完整采样帧输出；8 位 PCM 转为无符号表示，其余整数保持小端有符号。浮点 TTA 维持 `WAVE_FORMAT_IEEE_FLOAT`。
- 无共享解码状态，各 Reader 拥有自己的流、缓存和解码状态。

### FLAC

保留 STREAMINFO 的采样率、声道和位深，使用 libFLAC 回调解码；MD5 检查设置与原版一致。读取前清零 Buffer 长度，容量不足一个采样帧时拒绝请求，EOF 返回 `S_FALSE` 且长度为 0。

定位将毫秒转为 64 位采样位置，检查 libFLAC 定位结果；读取中断后先清理 libFLAC 的中断状态再定位。CRC、读错误及截断不会伪装为正常结束，错误状态保持到显式定位恢复。

### TTA

恢复 TTA1 的 22 字节头、CRC、每帧长度表、Rice 自适应参数、滤波和预测状态、声道差值还原。滤波使用显式 32 位无符号回绕，避免现代编译器对有符号溢出作错误优化。

历史 format 3 使用双倍内部通道状态恢复符号、指数和尾数；1、2、6 声道输出已与原 DLL 逐字节比较。帧长度为 `floor(sampleRate * 256 / 245)`，Seek 定位目标帧并丢弃帧前缀，按目标采样输出。

头、帧 CRC 验证失败会返回错误。仅定位表 CRC 损坏时，允许顺序解码并关闭 Seek 能力。TTA 标签维持宿主委托，不额外引入另一套标签实现。

## 标签与封面保存

### 标签

- FLAC Vorbis Comment 使用 UTF-8；保留枚举顺序、未修改的重复值、自定义字段和 ReplayGain。
- Get 按 ASCII 字母忽略大小写，返回最后一个匹配值。修正原版将 `[` 与 `{` 等字符也当成同一字符的问题。
- Set 修改指定字段；空值删除该字段；`Set(nullptr, nullptr)` 删除全部可编辑文字字段。
- 原有块尽量保留原字节；STREAMINFO、SEEKTABLE、APPLICATION、CUESHEET 以及压缩音频均不重建。
- 先验证修改后的序列化结果，再接受内存修改。超出单块或总量限制时返回失败，已有字段保持不变。

### 混合外部标签

原版打开 FLAC 时会合并宿主通用标签，保存前清理通用文字标签。若只写 native Comment 而保留旧外部文字，删除字段后下次打开可能从 ID3／APE 再次读出。

重建版在宿主提供通用标签时，将已经合并的字段写入 native Comment，并在同一临时文件事务中清理可安全处理的 ID3v2.2/2.3/2.4 文字帧、APE 文字、ID3v1 和 Lyrics3；保留外部 APIC/PIC、未知帧及 APE 二进制项。清理不会先修改原文件。

带全局 unsynchronization、扩展头或压缩／加密文字帧等尚未实现安全重写的 ID3，修改文字标签会返回 `E_NOTIMPL`，不把已删除字段悄悄保留为后备值。读取和播放不因此禁用。

### 封面

- 实现 Thumbnail 的 Count、At、Add、Replace、Remove 和 mask 语义。
- 默认优先枚举 type=3 的正面封面，保留其他原始图片类型。
- 新增 PNG/JPEG/GIF 时读取尺寸和色深，写入正确 PICTURE 属性；无需操作系统图像解码器。
- 最多暴露 64 张图片，单张新增数据上限 `16 MiB - 1024`，单 metadata block 上限由 FLAC 的 24 位长度决定，总 metadata 上限 64 MiB。
- 无法作为可编辑图片显示的块，包括 URL 型或超限旧图，作为原始块保留；删除选中图片不误删其余块。

### 提交与回滚

旧宿主在最终 Release 时保存，新宿主可通过独立 QI 接口显式 Commit，取得真实写盘结果。显式提交只尝试一次，即使失败，最终 Release 也不会再次写盘；重试需重新打开 Reader。接口布局、终结语义与调用顺序见 [COMMIT_INTERFACE.md](COMMIT_INTERFACE.md)。

保存先生成完整新文件；校验文件长度、最后写入时间，防止覆盖已被外部改动的文件。路径可替换时使用 `ReplaceFileW`；宿主持有不允许删除共享的文件句柄时才创建回滚备份、使用可写流，失败后恢复备份。回滚本身失败时保留恢复文件，并通过调试日志提供路径。

这比原版的直接更新更稳健，但宿主阻止路径替换时的流写入并非断电原子操作。原版不调用新增接口，仍不能收到最终 Release 保存的返回值；本轮重建宿主的文件属性窗口已接入新接口，显示具体错误并保留未保存编辑。

## 与原版有意不同的行为

| 原版问题或限制 | 重建行为 |
| --- | --- |
| Read 忽略宿主容量，可能写越界 | 校验容量，按采样帧限制输出 |
| EOF 残留上次 Buffer 长度 | 每次 Read 先清零 |
| 部分 Seek 失败仍返回成功 | 传递失败，成功才更新位置 |
| FLAC 32 位可打开但没有 PCM | 使用 libFLAC 1.5.0 正确输出 32 位 PCM |
| TTA 时长丢弃不足一秒的部分 | 64 位计算毫秒时长 |
| 粗糙的 `OR 0x20` 标签比较 | 仅折叠 ASCII 字母 |
| 一张小封面、属性不完整 | 多张图片，保留类型并写入真实尺寸 |
| 窄字符路径保存与部分直接覆盖 | Unicode 路径、预生成、备份及回滚 |
| 异常数据可能导致无界处理 | metadata、帧长度、声道及计数都有边界 |

## 内存、复制与体积优化

- 原始 metadata 块采用不可变共享存储；PICTURE 数据引用原块切片，未修改标签的原始文本引用块内数据，避免重复保存整个封面和文本。
- Set 通过计算序列化长度校验上限，不再为每次修改构造全部 metadata；只有提交时序列化改变的块。
- 文件复制复用一个 256 KiB 缓冲区；原子替换成功时跳过完整备份，只有流回写才复制备份。
- FLAC 解码保留 PCM 缓冲容量，避免每帧清空再扩容产生的重复初始化；TTA 的 64 KiB 位流缓存只在打开 TTA 时分配，CRC 表改为编译期常量。

本机固定压力样本含四张约 4 MiB 的图片数据，连续修改 200 次标签，各版本运行三个独立进程。上一构建的编辑耗时中位数 733.305 ms，本轮 2.532 ms；观测峰值私有提交内存从 52,117,504 字节降至 18,395,136 字节，约减少 64.7%。这是特定大封面编辑场景，不是播放解码倍速，也不包含最终保存时间。

本轮 DLL 比上一构建增加 1,024 字节（约 0.66%），用于新增接口、错误处理和共享存储。对比关闭 SIMD 仅省 512 字节，降低内联等级未省空间，最终保留 SIMD、`/Ob2` 和尺寸优化。没有声称 DLL 体积下降。

## 已知限制

1. **旧宿主保存回执**：原 Metadata 仍没有 Commit 槽；原版不查询新接口，最终 Release 保存错误只能调试日志反馈。本轮重建宿主通过独立可选接口取得真实结果。正在播放的共用 Reader 的歌词写入继续旧生命周期，不强行终结播放。
2. **输入边界**：本次恢复 native FLAC/TTA 与可定位 IStream；不承诺 Ogg FLAC、MP4 FLAC、不可定位网络流、TTA2 或加密 TTA。
3. **外部标签特殊编码**：全局 unsynchronization、扩展头、压缩／加密文字帧等暂不重写；明确拒绝文字修改，原字节保留。
4. **位深／机器范围**：TTA 的 format 1 32 位整数分支未获得独立编码器样本验证；已验证的 TTA 32 位是历史浮点分支。不宣称非 SSE2 CPU、XP SP2 或 XP x64 已通过测试。
5. **路径与保存环境**：中文与 emoji 路径已验证，但临时文件 API 仍受传统 MAX_PATH 条件约束；超长路径、断电、磁盘完全耗尽并同时回滚失败不在本次通过项中。
6. **验证边界**：现代 libFLAC 对异常输入的接受范围可能与 1.2.1 不同。现有证据支持已列有效格式和交互的兼容，不能证明所有输入、所有系统上完全等价。
